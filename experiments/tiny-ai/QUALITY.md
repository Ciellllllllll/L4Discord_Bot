# 自作モデルの品質改善実験

## 方針

既製モデルや外部教材を使わず、抽出したDiscord本文の同一スナップショットで複数設定を比較します。原本のデータベースや以前のモデルは変更しません。目標は短文の自然さと文字予測精度の改善であり、返信関係の学習やDiscordへの接続はこの実験に含めません。

## 評価の分離

`quality.py prepare`は既存の`data/train.json`と`data/val.json`を、学習・調整・最終評価の3つに再分割します。全角半角、大文字小文字、句読点、空白だけが違う本文をまとめ、同じ分割先に配置します。意味の近い文章を完全に検出する処理ではありません。

- 学習: モデルの重みを調整するために使用
- 調整: 学習を止める時点と最良モデルの選定に使用
- 最終評価: 選定結果をファイルに確定した後にだけ使用

全候補は新しい分割でゼロから学習します。既存の学習済みモデルは最終評価用の本文を学習している可能性があるため、品質比較には流用しません。生成時の固定した書き出し、乱数、温度も最終評価の結果に合わせて変更しません。

## 実験方法

モデルの幅32・64・96、層数1・2を候補にします。最初に幅32・1層を8周学習して比較基準を作り、改善候補は最大32周学習します。各周では全学習例を1回ずつ使います。最初は学習の強さを徐々に上げ、後半は滑らかに下げます。調整用の誤差に十分な改善が6周なければ、その学習を打ち切ります。候補は調整用の文字予測誤差が最小のモデルを選定し、時間に余裕があるときは選ばれた設定を別の乱数で再試行します。

発言を長さの近いもの同士でまとめて計算し、余白の計算を減らします。これによって学習対象が省かれることはありません。CPUは0.75コア分、メモリは512MiBに制限し、全候補を直列に実行します。探索と最終評価には合計3,300秒の期限を設け、最後の評価用に180秒を確保します。期限で中断した候補は選定対象にしません。

生成文は短い固定の書き出しから、温度0.6と0.8で各24件ずつ確認します。温度とは次の文字を選ぶ際のばらつきであり、小さくするとよくある表現に寄ります。同じ文字列の繰り返し、空の続き、学習本文との完全一致も記録します。これらの数値は文章の意味や正確さを測るものではありません。

## 実行手順

作業ディレクトリ（`experiments/tiny-ai`など）で実行します。

```sh
# 初回のみ。既存の出力先への上書きは拒否します。
python3 quality.py prepare --source data --out quality-data
docker build -t l4-tiny-ai:quality-v2 .
./ai-quality suite --data /data --out /runs/quality-v2 --budget 3300

# 選ばれたモデルで生成します。新しい比較実験には別のoutを指定してください。
./ai-quality generate --prompt '今日は' --count 5
```

通常の生成コマンドは同じ文字の連打を3文字で打ち切ります。これは生成文の連打を抑えるための後処理であり、学習能力の改善ではありません。`--max-same-char 0`で無効にできます。比較実験の生成評価はこの制限なしで実施し、制限後の結果で比較実験の数値を書き換えることはしません。

`runs/quality-v2/selection.json`に採用モデル、`trials.json`に比較結果、`summary.json`に最終評価の集計、`evaluation.json`に生成文を保存します。生成文と教材はローカル環境に保持し、Gitへ含めません。実験を止めたい場合は`docker ps --filter ancestor=l4-tiny-ai:quality-v2`でコンテナを確認し、そのIDに対して`docker stop`を実行してください。以前の`./ai generate ...`も引き続き使えます。

## 検証コマンド

```sh
python -m unittest discover -s experiments/tiny-ai -p test_benchmark_data.py
python -m unittest discover -s experiments/tiny-ai -p test_quality.py

# 実験コンテナ内で実行する場合
docker run --rm --network none --cpus 0.75 --memory 512m --memory-swap 512m \
  --entrypoint python l4-tiny-ai:quality-v2 \
  -m unittest test_model test_benchmark_data test_quality test_pipeline test_generation
```

これらのテストでは、合成データで評価用ファイルを壊した状態でも学習が完了すること、選定済みモデルの再読込、同じモデルなら同じ評価になることを検証します。
