# 自作モデルの品質改善実験

## 方針

既製モデル・外部教材を使わず、最初に抽出したDiscord本文の同一スナップショットで比較します。
原本のDBや前回のモデルは変更しません。今回の目標は短文の自然さと文字予測の改善です。
返信関係の学習やDiscordへの接続は今回含みません。

## 評価の分離

`quality.py prepare`は既存の`data/train.json`と`data/val.json`を再分割します。
全角半角・大文字小文字・句読点・空白だけが違う本文をまとめ、同じ分割先に置きます。
意味の近い文章を完全に検出する処理ではありません。

- 学習: 6,237件。モデルの重みを調整するために使用。
- 調整: 864件。学習を止める時点と最良モデルの選定に使用。
- 最終評価: 804件。選定結果をファイルに確定した後にだけ使用。

全候補は新しい分割でゼロから学習します。前回の学習済みモデルはこの最終評価用の本文を
学習している可能性があるため、品質比較に流用しません。
生成時の固定した書き出し・乱数・温度も、最終評価の結果に合わせて変更しません。

## 実験方法

モデルの幅32/64/96、層数1/2を候補にします。最初に幅32・1層を8周学習して比較基準を作り、
改善候補は最大32周学習します。各周は全学習例を1回ずつ使います。
最初は学習の強さを徐々に上げ、後半は滑らかに下げます。
調整用の誤差に十分な改善が6周なければ、その学習を打ち切ります。
候補の選定は調整用の文字予測誤差が最小のモデルです。
時間に余裕があるときは、選ばれた設定を別の乱数で再試行します。

発言を長さの近いもの同士でまとめて計算し、余白の計算を減らします。
これによって学習対象を省くことはありません。
CPUは0.75コア分、メモリは512MiBで、全候補を直列に実行します。
探索と最終評価には合計3,300秒の期限を設け、最後の評価用に180秒を確保します。
期限で中断した候補は選定対象にしません。

生成文は短い固定の書き出しから、温度0.6と0.8で各24件ずつ確認します。
温度は次の文字を選ぶ際のばらつきです。小さくするとよくある表現に寄ります。
同じ文字列の繰り返し、空の続き、学習本文との完全一致も記録します。
これらの数値は、文章の意味や正確さを測るものではありません。

## 実行

VPSの`/opt/l4-tiny-ai`で実行します。

```sh
# 初回のみ。既存の出力先への上書きは拒否します。
python3 quality.py prepare --source data --out quality-data
docker build -t l4-tiny-ai:quality-v2 .
./ai-quality suite --data /data --out /runs/quality-v2 --budget 3300

# 選ばれたモデルで生成。新しい比較実験には別のoutを指定してください。
./ai-quality generate --prompt '今日は' --count 5
```

通常の生成コマンドは同じ文字の連打を3文字で打ち切ります。
これは生成文の確認で見つかった連打への対策で、学習能力の改善ではありません。
`--max-same-char 0`で無効にできます。比較実験の生成評価は、この制限なしで実施しました。
制限後の結果で比較実験の数値を書き換えることはしません。

`runs/quality-v2/selection.json`に採用モデル、`trials.json`に比較結果、
`summary.json`に最終評価の集計、`evaluation.json`に生成文を保存します。
生成文と教材はVPS内に保持し、Gitへ含めません。
止めたい場合は`docker ps --filter ancestor=l4-tiny-ai:quality-v2`で実験コンテナを確認し、
そのIDに対して`docker stop`を実行します。前回の`./ai generate ...`は引き続き使えます。

## 検証

### 2026-11-15 実機での結果

探索は約22分44秒で完了し、最終評価も1時間の上限内で終了しました。
5回の学習を行い、幅96・2層・439,680パラメータの14周目を選定しました。
選定用データだけで決めた結果を保存してから、最終評価用804件を採点しました。

| 候補 | パラメータ数 | 最良の周 | 調整用の予測誤差 |
| --- | ---: | ---: | ---: |
| 今回の比較基準 | 84,704 | 8 | 3.7322 |
| 小型・学習方法を調整 | 84,704 | 23 | 3.6634 |
| 幅64・2層 | 243,968 | 20 | 3.5878 |
| 幅96・2層（採用） | 439,680 | 14 | 3.5512 |
| 幅96・2層、別の乱数 | 439,680 | 12 | 3.5604 |

最終評価用の予測誤差は、今回の比較基準が3.8543、採用モデルが3.6801でした。
これは文字予測の誤差が約4.5%減ったという結果で、会話の品質が4.5%向上したことを意味しません。
評価用本文の約0.48%の文字は学習側の語彙に存在せず、未知文字として採点しています。
採用モデルの学習プロセスの最大RSSは約320MiB、モデルファイルは約1.8MiBでした。

同じ書き出し・温度・乱数で各モデル48件を生成しました。
入力「明日は」から「明日は無理だよ」、入力「それは」から「それはほんと思う」が出る一方、
「今日は違うない」などの不自然な表現も残っています。
平均反復指標は比較基準0.0232、採用モデル0.0341で、反復については改善していません。
学習本文との完全一致は1/48件と2/48件で、採用モデルの一致は同じ「ありがとうね」が2回でした。
短い定型表現の一致だけで丸暗記の有無は断定できません。部分的な一致の検査は未実装です。

連打の抑制はこの生成確認後に利用コマンドへ追加しました。モデルの重みは変えておらず、
上記の評価値や生成比較を制限後の結果に置き換えていません。
元のモデル・実行イメージ・教材を残し、新しい生成コマンドからの再読込もVPSで確認しました。
関連テスト8件、追加した連打制限1件と生成用乱数の再現性1件のテストが成功しています。
生成用の乱数はモデル読込後に設定し、評価時と利用コマンドの同じseedが一致するようにしました。
既存Botはコンテナの起動継続、PostgreSQLはhealthyを確認しました。
Discord画面上での応答確認はしておらず、このモデルとのDiscord連携も未実装です。

実験終了後にVPS上の実験コンテナ消滅と評価成果物の完成を確認しましたが、
手元のSSH接続だけが残ったため、その接続プロセスを終了しました。
接続コマンドの終了コードによる成功判定ではなく、保存結果と新規接続での生成で完了を確認しています。

数値の詳細は`quality-results-2026-11-15.json`、生成文全体はVPSの
`runs/quality-v2/evaluation.json`に保存しています。

確認した出力例を再現するコマンド:

```sh
./ai-quality generate --prompt '明日は' --seed 1021 --count 1
# 明日は無理だよ
./ai-quality generate --prompt 'それは' --seed 1060 --count 1
# それはほんと思う
./ai-quality generate --prompt '今日は' --seed 1012 --count 1
# 今日は!!! （連打の制限が働く例）
```

### 検証コマンド

```sh
python -m unittest discover -s experiments/tiny-ai -p test_benchmark_data.py
python -m unittest discover -s experiments/tiny-ai -p test_quality.py

# VPSの実験ディレクトリで実行
docker run --rm --network none --cpus 0.75 --memory 512m --memory-swap 512m \
  --entrypoint python l4-tiny-ai:quality-v2 \
  -m unittest test_model test_benchmark_data test_quality test_pipeline test_generation
```

合成データで評価用ファイルを壊した状態でも学習が完了すること、選定済みモデルの再読込、
同じモデルなら同じ評価になることも検証します。
