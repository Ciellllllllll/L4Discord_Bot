# 日本語解析ワーカーのAPI仕様

Botは日本語の解析処理を別プロセスへ依頼できます。日本語解析ワーカーは形態素解析と五七五の検出をHTTPで提供します。形態素解析とは文章を単語に分けて読みや品詞を求める処理です。待ち受け先は同じホスト内から接続するループバックアドレスに限定しており、既定値は`127.0.0.1:8787`です。

ワーカーの実装は[main.go](../workers/japanese-worker/main.go)、Bot側の通信処理は[japaneseAnalysisClient.ts](../src/features/japaneseAnalysis/japaneseAnalysisClient.ts)にあります。起動方法と設定は[日本語解析ワーカーの起動と運用](japanese-worker-deployment.md)を参照してください。

## 要求と応答の共通仕様

解析要求はJSONで送信します。本文は64 KiB（65,536バイト）まで読み取ります。未知のフィールド、JSONの解析エラー、上限超過による解析失敗を検出すると、HTTP 400を返します。

ワーカーは解析前に、URL、Discordのユーザーやロールへのメンション、チャンネルへの言及、カスタム絵文字、コードブロック、インラインコードを空白へ置き換えます。その後、連続する空白を一つにまとめます。Bot側の通信処理自体は本文を加工せず、各機能の呼び出し元がそれぞれの条件で本文を処理します。

応答の形式はHTTPの状態コードによって異なります。正常時の応答だけを前提にせず、先に状態コードを確認してください。

| 状態コード | 条件 | 応答 |
| --- | --- | --- |
| 200 | 解析成功、候補なし、または稼働確認成功 | 各APIの正常応答 |
| 400 | JSONの解析失敗、未知のフィールド、本文上限による解析失敗 | `{"error":"invalid_json"}` |
| 400 | 五七五以外の`rule` | 検出応答の`error`に`only strict 5-7-5 is supported` |
| 405 | 対象APIで受け付けないHTTPメソッド | 本文なし |
| 500 | 五七五解析の失敗 | 検出応答の`error`に`senryu_analysis_failed` |
| 500 | ハンドラー内のパニックから復帰した場合 | `{"error":"internal_error"}` |

## 稼働確認`GET /health`

ワーカーがHTTP要求へ応答できる場合、HTTP 200と次のJSONを返します。解析結果の正しさやDiscordへの接続状態を確認するAPIではありません。

```json
{
  "ok": true
}
```

## 五七五の検出`POST /analyze/senryu`

解析する文章を`content`に指定します。`rule`は`[5, 7, 5]`のみを受け付け、省略時、`null`、空配列の場合も五七五として扱います。

```json
{
  "content": "解析する文章",
  "rule": [5, 7, 5]
}
```

候補が見つかると、最初の候補を`text`と三つの`phrases`に返します。次のJSONは応答の構造例です。

```json
{
  "matched": true,
  "text": "上五 中七 下五",
  "phrases": ["上五", "中七", "下五"],
  "error": null
}
```

候補が見つからない場合、解析対象が空の場合、または候補を三句に分割できない場合は、次の正常応答を返します。`matched: false`は通信失敗と区別します。

```json
{
  "matched": false,
  "text": null,
  "phrases": [],
  "error": null
}
```

## 形態素解析`POST /analyze/morph`

解析する文章を`content`に指定します。

```json
{
  "content": "東京"
}
```

単語ごとの情報は応答の`tokens`に格納します。次のJSONは構造を示す例であり、品詞や読みの実際の値は辞書によって変わります。

```json
{
  "tokens": [
    {
      "surface": "東京",
      "base": "東京",
      "reading": "トウキョウ",
      "pos": ["名詞", "固有名詞", "地域", "一般"],
      "isProperNoun": true,
      "isOov": false
    }
  ],
  "error": null
}
```

| フィールド | 内容 |
| --- | --- |
| `surface` | 本文に現れた表記 |
| `base` | 辞書の基本形。取得できない場合は`surface` |
| `reading` | 辞書の読み。取得できない場合は`surface` |
| `pos` | 辞書の先頭4項目から空欄と`*`を除いた品詞情報。残らない場合は`["未知語"]` |
| `isProperNoun` | `pos`に`固有名詞`を含むか |
| `isOov` | 辞書の特徴情報が7項目未満かを基準にした未知語判定 |

解析対象が空の場合は`{"tokens":[],"error":null}`を返します。助詞や助動詞も解析結果に含まれますが、語彙学習機能では学習前に除外します。文型学習では、別の処理で一部の助詞を残します。

## Bot側の失敗判定

Bot側の通信処理は成功を`ok: true`、失敗を`ok: false`で返します。失敗理由は次のように分類します。

| `reason` | 内容 |
| --- | --- |
| `http_error` | HTTP応答が成功の状態コードではない |
| `invalid_json` | 成功応答の本文をJSONとして読めない |
| `invalid_response` | フィールドの型などが期待する形式と異なる |
| `timeout` | 設定した時間を超えて要求が中断された |
| `unreachable` | その他の通信例外が発生した |

五七五の検出応答では、`matched: true`のときに`phrases`が三つあることも検査します。正常な形式で返された応答は、`error`の文字列だけを理由に通信失敗へ分類し直すことはありません。現在のワーカーは解析エラーをHTTP 400または500で返すため、Bot側では`http_error`になります。
